## Architektur-Erkenntnisse

### Datenfluss OpenWebUI → LLM (Stand nach Session)
```
OpenWebUI (:8086)  →  Agent API (:11436)  →  llama-server (:8090)   [GPU, grosses Modell]
                                           →  Ollama (:11434)        [CPU, kleines Modell]
                      GPU Manager (:8099)  →  steuert llama-server Prozess
```

### Wichtig: Ollama ist de facto nur für Strategy-Modell
- `LLM_ANSWER_BACKEND=openai` → alle Antworten gehen an llama-server
- Ollama dient nur für qwen2.5:3b (Tool-Routing)
- OpenWebUI zeigt `llama4:latest` als Modell, aber dahinter antwortet gpt-oss-120b
- **TODO**: `/api/tags` sollte aktuelles llama-server Modell anzeigen

### Ollama-Entfernung: NICHT jetzt
- Ollama hat Abhängigkeiten in: Docker-Compose, Agent API, Batch-Scripts, OpenWebUI
- Inventarisierung nötig bevor Entfernung
- Aktuell: Ollama bleibt für kleines Modell (Strategy), llama-server für grosses

## Lessons Learned

1. **WEBUI_AUTH=false** funktioniert nur wenn KEINE User in der DB existieren
2. **llama-server `-hf`** ist extrem praktisch — kein manueller GGUF-Download nötig
3. **Blackwell Unified Memory**: Alle Modelle laufen mit `-ngl 999` (full GPU offload)
4. **Code ist NICHT als Volume gemountet** → nach jeder Änderung: `docker cp` + restart
5. **search_hybrid()** muss AUCH den Suchmodus respektieren, nicht nur `search_chunks()`
